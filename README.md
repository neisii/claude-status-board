# claude-agents-board

`server-status-board`·`digital-clock-board`와 같은 자리(터미널 분할)에 띄워 두는 Claude Code 세션 현황판. 10초 간격으로 `claude agents --all --json`을 호출해서, 지금 떠 있거나 최근에 떠 있던 세션들을 상태별로 묶어 한 줄씩 보여준다. 조회·표시만 하는 읽기 전용 도구다 — 세션을 깨우거나 종료하지 않는다.

설정 파일이 따로 없다. `claude` CLI가 PATH에 있으면 그대로 실행된다.

## 실행

```
npm install
npm start
```

종료는 Ctrl+C.

소스를 고치는 중이면 `npm run dev`(`node --watch index.js`)로 띄운다 — 파일이 바뀌면 자동으로 재시작된다(Node 18.11+ 내장 기능). 다만 이 모드에서는 Ctrl+C를 **두 번** 눌러야 완전히 꺼진다: 이 보드는 `n` 키를 받으려고 터미널을 raw mode로 두기 때문에 첫 Ctrl+C는 시그널이 아니라 키 입력으로 보드(`index.js`)에 들어가 보드만 정상 종료시키고, `--watch`는 `Completed running 'index.js'. Waiting for file changes before restarting...`를 띄운 채 남는다. raw mode가 풀린 뒤의 두 번째 Ctrl+C가 watch·npm까지 끝낸다. 그래서 평소 띄워 두는 용도의 `npm start`는 `--watch` 없이 실행한다(`server-status-board`·`digital-clock-board`는 키 입력을 안 받아 raw mode가 아니므로 `npm start`가 `--watch`여도 Ctrl+C 한 번에 꺼진다).

## 화면 구성

```
╭───────────────────────────────────╮
│ Claude 세션 현황  (22:02:33 갱신) │
│                                   │
│ [작업중]                          │
│   widget-master(방금)             │
│ [대기] (5개, n으로 펼치기)        │
│ [종료] (8개, n으로 펼치기)        │
│                                   │
│  transcript 수정 시간 경과 추정값 │
╰───────────────────────────────────╯
```

TTY라 raw mode가 켜진 상태에서는 제목 줄 오른쪽에 `N키: Next`도 함께 뜬다(이름까지 보기 절 참고). 테두리는 내용 길이와 무관하게 항상 그 패널의 실제 행 수(`process.stdout.rows`)만큼 고정 높이로 뜬다(아래 "높이" 절 참고) — 세션이 적을 땐 위 예시처럼 테두리 안쪽에 빈 칸이 남는다.

세션 하나당 레코드 하나를 분류해 상태별로 묶는다. 분류 기준(`index.js`의 `categorize`):

- `pid`가 있으면(지금 살아있는 프로세스) `status` 필드를 믿는다: `busy` → **작업중**. `status`가 `idle`이면서 `state`가 `working`이면 **상주(루프 대기)**. 그 외(`idle`이면서 `state`도 `working`이 아닌 경우) → **대기**.
- `pid`가 없으면(프로세스가 떠 있지 않음) 마지막 `state`를 본다: `blocked` → **막힘**, `failed` → **실패**, 그 외(`done`/`stopped` 등) → **종료**.
- 같은 이름이 여러 레코드로 남아 있으면(세션 재개 등) `startedAt`이 가장 큰 것만 쓴다.
- 묶음은 조치가 필요한 쪽(막힘·실패)이 위, 끝난 세션(종료)이 아래로 고정 순서다(막힘→실패→작업중→상주(루프 대기)→대기→종료). 내용이 없는 묶음은 줄 자체를 숨긴다.

**상주(루프 대기)**는 `/loop`처럼 긴 주기(예: 25분)마다 짧게 깨어나는 세션을 위한 묶음이다(실측 2026-10-29, patrol-master). 그 틱 순간에만 `status=busy`이고 나머지 대부분은 `status=idle, state=working`으로 남는데, 이 보드의 10초 폴링으로는 그 짧은 busy 순간을 거의 못 잡아서 지금 루프를 돌리는 중인데도 항상 **대기** 묶음에 잡혀 "작업중이 아닌 것처럼" 보이는 문제가 있었다. 세션 이름이 아니라 `status`/`state` 조합으로 판정하므로, architect-master처럼 같은 조건에 걸리는 다른 세션도 자동으로 이 묶음에 들어간다.

### 이름까지 보기(n)

한 번에 한 묶음만 세션 이름까지 펼쳐 보여준다. 켰을 때 기본은 **작업중**의 1페이지고, `n`을 누르면 지금 묶음에 다음 페이지가 있으면 그쪽으로(페이지는 아래 "높이" 절 참고), 마지막 페이지였으면 다음 묶음(막힘→실패→작업중→상주(루프 대기)→대기→종료→다시 처음, 비어 있는 묶음은 건너뜀)의 1페이지로 넘어간다. 지금 안 펼쳐진 묶음은 `[라벨] (N개, n으로 펼치기)` 한 줄로만 접혀 보인다. 단축키 안내(`N키: Next`)는 제목 줄 오른쪽에 뜬다. 터미널이 TTY가 아니면(예: 출력을 파일로 리다이렉트) Ink가 raw mode를 못 켜므로 이 기능은 조용히 꺼지고 제목 줄의 단축키 안내도 안 뜬다 — 항상 작업중 묶음의 1페이지만 펼쳐진 채로 멈춘다.

실측 결과 하나는 적어 둔다: `pid` 없고 `state`가 `blocked`인 레코드를 재개 시도했더니 실제로는 이미 다시 살아나 있던 사례가 있었다(`dev-session-launch` 스킬 문서 참고). 즉 이 보드의 **막힘·실패는 "지금 확실히 그 상태"가 아니라 "조회 순간 그렇게 보였다"**는 뜻이다 — 뭔가 조치하려면 재확인부터 한다.

### 이름 뒤 `(N분/시간/일 전)`

`claude agents --json`에는 "마지막으로 뭘 했는지"의 시각이 없다(`startedAt`은 세션을 처음 띄운 시각일 뿐이라, 오래 떠 있는 세션은 실제로 방금 움직였어도 계속 옛날 시각으로 보인다). 그래서 대신 그 세션의 transcript 파일(`~/.claude/projects/<cwd를 인코딩한 폴더명>/<sessionId>.jsonl`)의 최종 수정 시각을 "마지막 활동 시각"의 대리값으로 쓴다. 폴더명 인코딩은 실측으로 확인한 규칙이다(`cwd`에서 영숫자·하이픈이 아닌 글자를 전부 `-`로 바꾼 것, 예: `C:\Users\...` → `C--Users-...`). 공식 API가 주는 값이 아니라 추정값이라는 뜻으로 화면 아래쪽 오른쪽 끝에 `transcript 수정 시간 경과 추정값`이라고만 짧게 띄워 둔다(이전에는 긴 설명 문장이었는데, 짧은 태그로 줄였다). transcript 파일을 못 찾으면 `startedAt`으로 되돌아간다.

Claude Code 앱 자체의 Agents 패널에 나오는 "그 세션이 지금 정확히 뭘 하고 있는지"의 한 줄 설명(자유 텍스트)은 이 방법으로도 못 가져온다 — 그건 외부에 노출되는 API/파일이 없다. 이 보드가 보여줄 수 있는 건 상태 분류 + 대략적인 경과 시간까지다.

- 갱신에 실패하면(예: `claude` CLI 호출 실패) 직전 값을 그대로 둔 채 제목에 `(HH:MM:SS 갱신 실패, 직전값 표시)`만 빨간색으로 띄운다. 죽지 않는다.

## 폭

`server-status-board`처럼 그 순간 내용(제목·각 묶음 줄·하단 태그) 중 가장 긴 줄의 실제 터미널 칸 수(`string-width`)를 재서 테두리 폭을 맞춘다. 다만 이름이 많이 묶이면 한 줄이 한없이 길어질 수 있어 `MAX_CONTENT_WIDTH`(72칸)로 상한을 두고, 그보다 긴 줄은 테두리 안에서 줄바꿈된다. 다른 두 보드와 나란히 띄워도 되지만, 그쪽들처럼 폭을 서로 맞춰 역산해 두지는 않았다(묶이는 세션 수에 따라 줄 수 자체가 늘었다 줄었다 하기 때문).

## 높이

Ink는 가로 폭은 터미널에 맞춰 강제하지만 세로 높이는 신경 쓰지 않는다 — 그래서 펼친 묶음에 이름이 많으면 테두리·하단 태그까지 포함한 전체 줄 수가 분할 패널의 실제 행 수(`process.stdout.rows`)를 넘어버리고, 패널은 그 넘치는 만큼 스크롤해서 **테두리 위쪽(제목 줄 포함)이 패널 밖으로 밀려 올라가 보이지 않는** 문제가 생긴다(실측: 패널이 11행 정도일 때 6개짜리 묶음을 펼치면 재현됨).

그래서 보드 테두리를 처음부터 `process.stdout.rows` 그대로 고정 높이로 둔다 — 세션이 적어서 내용이 짧아도 좌우 테두리가 패널 바닥까지 늘어난다(남는 자리는 빈 칸). 펼친 묶음에 이름이 그 안에 다 못 들어가면 `...그 외 N개 더`로 잘라 보여주던 예전 방식 대신, **페이지로 나눠서 `n`으로 넘겨 본다**: 한 페이지에 들어가는 개수(`pageSize`)는 전체 줄 수에서 접힌 다른 묶음 한 줄씩과 펼친 묶음 헤더 한 줄을 뺀 나머지다. 예를 들어 작업중이 10개고 `pageSize`가 3이면 `n`을 누를 때마다 1~3 → 4~6 → 7~9 → 10(1/4~4/4페이지) 순으로 보여주고, 마지막 페이지에서 `n`을 또 누르면 다음 묶음의 1페이지로 넘어간다(렌더 쪽과 키 입력 쪽이 같은 `computeGroupLayout`/`nextCursor` 계산을 쓰므로 페이지 번호가 어긋나지 않는다). 페이지가 2개 이상이면 묶음 머리글에 `(2/4페이지)`처럼 표시된다. 그래도 공간이 아예 없으면(패널이 너무 작으면) 그 묶음도 다른 묶음처럼 `[라벨] (N개, 화면 높이 부족해 숨김)` 한 줄로 접힌다. 터미널 크기를 바꿨을 때는 다음 10초 갱신이나 `n` 키를 눌러야 반영된다(리사이즈 이벤트를 따로 구독하지 않는다).

맨 아래 `transcript 수정 시간 경과 추정값` 태그(미주)는 내용이 얼마나 짧든 항상 하단 테두리 바로 위 줄에 온다. 제목+묶음 줄들을 한 Box로 묶고, 그 Box와 미주를 바깥 Box(고정 높이, `justifyContent: 'space-between'`)의 양 끝에 둬서, 남는 빈 줄이 둘 사이로 몰리게 했다 — 세션이 적을 때는 묶음 목록과 미주 사이에 빈 칸이 생기고, 꽉 찰 때는 거의 붙어 보인다(둘 다 실제 렌더로 확인).

## 폴링 주기

10초. `claude agents --all --json` 호출 자체가 가볍지 않아(실측 0.5~0.6초) 더 짧게 잡지 않는 걸 권한다.
